# Rex Machina

A shelter dog walks home across nine days to the family that gave her away, and
has to get past the robot dog they replaced her with.

**Play it:** https://sritej.itch.io/rex-machina
**Case study:** https://sritejcanchi.github.io/rex-machina/ (what I built, the decisions, and the lessons)
**Capstone for:** ELVTR, Multi-Agent AI for Game Development, 2026.

Every line of content in the game was generated by the agent pipelines in
`pipelines/`. Nothing in the game code authors game content.

---

## The pipeline, end to end

```
docs/gdd_rex_machina.md          the design document, written by hand
        |
        v
  pipelines/a4-canon-index-rag       RAG over the GDD and story bible
        |                            -> DT_NemesisReads, DT_ArenaPhases,
        |                               DT_JourneyHazards
  pipelines/a6-retry-read-ger        generate, evaluate, refine, circuit break
        |                            -> DT_RetryReads
  pipelines/a7-copy-desk-style       scored style enforcement
        |                            -> DT_JourneyBeats
        v
  tools/sync_datatables.py           copies each file byte for byte, checksums
        |                            both ends, refuses to finish on a mismatch
        v
  data/*.json                        what the game actually loads
        |
        v
  index.html + game.js               the browser build, deployed to itch.io
```

Two more pipelines feed the design rather than the data.
`pipelines/a5-architect-goal-agent` reads the GDD, scans the game source and
writes a missing feature into it. `pipelines/a8-nine-days-narrative` is the
journey ledger the Acts 1 and 2 design came from.

## What the pipelines produced, and where you see it

| In the game | Rows | From |
|---|---|---|
| The six chase encounters of Acts 1 and 2, with their telegraphs, escape windows and fail states | 6 | A4 |
| The three Act 3 arenas, their exits, cover and lighting | 3 | A4 |
| Everything the robot says during the fight | 24 | A4 |
| What it says when you respawn after losing | 6 | A6 |
| The journey beats | 3 | A7 |

42 rows across 5 tables. `data/MANIFEST.json` carries a sha256 for each.

## How to play

Acts 1 and 2 are six timing encounters. Something is hunting you, it telegraphs
before it commits, and you break on the turn after the tell. Go early or hold
too long and you are caught. Three of the six leave you limping if you fail
them, and the robot can see a limp.

Act 3 is the fight. Fifteen rounds, three arenas. The robot does not chase you,
it moves to the tile it thinks you are about to step on, and it tells you what
it measured off your movement while it does it. Reach the kid before the clock
or your legs run out. How well you ran the journey sets your starting stamina,
17 down to 14.

## Running it locally

```
python3 -m http.server 8000      then open localhost:8000
node tests/sim.js                29 headless tests, no browser needed
node qa/adversary.js             the adversarial QA agent, 1,519 checks
python tools/sync_datatables.py  re-copy the pipeline output into data/
```

Nothing to install. No API key. The game is static files.

The pipelines under `pipelines/` each run offline from recorded model turns,
and each takes `--live` with `ANTHROPIC_API_KEY` set to call
`claude-haiku-4-5` for real.

## Testing

`tests/sim.js` loads `game.js` headless and plays it. It proves the fight is
winnable from every journey outcome, that a wandering line loses, that the
robot never ends a round further away than it started, and that every line it
speaks came from a generated table.

`qa/adversary.js` is the Assignment 9 agent. It re-attempts five of the six
exploits GDD §3 says were closed, fuzzes 300 randomised fights, and probes each
encounter for winnability. It found three bugs in this build, all now fixed and
documented in `qa/README.md`. Runs are seeded (`RM_SEED`) and any finding exits 1.

| Level | Command | What it covers |
|---|---|---|
| Data | `python tools/sync_datatables.py --verify` | Every table matches its manifest hash and row count |
| Unit | `node --test tests/unit/` | Rex's observables, prediction, veto, charge, reads and RM-001, refused moves, stamina floor, table shape. Open bug RM-13 is a `todo` test |
| Integration | `node tests/sim.js` | The real game with the real tables, played headless |
| Adversarial | `node qa/adversary.js` | About 3,000 checks against the running build |
| End to end | `npm run test:e2e` | The real page in Chromium: the computer plays all six encounters and wins the fight, arrow keys, no browser errors. Timers are fast-forwarded and boards seeded |
| Pipelines | `python pipelines/<name>/tests/test_*.py` | Each content pipeline, replaying recorded model turns, no key |

`npm test` runs data, unit, simulation and the QA agent. `.github/workflows/ci.yml`
runs everything on each push and pull request, and only the jobs the change can
affect. No job needs an API key.

## Layout

```
index.html game.js data/    the playable build, deployed as is
tools/sync_datatables.py    pipeline output to game data, with checksums
tests/sim.js                headless tests
qa/                         the adversarial QA agent and its reports
pipelines/                  the five agent pipelines that made the content
docs/                       the GDD, and the Assignment 10 pipeline audit
```

## Unreal build

`docs/UNREAL-SETUP.md` lists the five row structs field by field. UE 5.5.
`tools/ue_import_datatables.py` imports every pipeline CSV as a DataTable in
one run, in the editor or headless from the command line.
`docs/UNREAL-BLUEPRINT-SPEC.md` is the Act 3 fight written out node by node,
with the three bugs the QA agent found marked at the lines that fix them.
