# Pasting the generated graphs

Sixteen graphs, generated by `tools/bp_gen.py` and written here as text. UE
rebuilds nodes and wires from this text on paste, so none of it is typed by
hand.

Regenerate any of them with, for example:

    python tools/bp_gen.py inbounds > generated/inbounds.txt

**Lint before pasting.** `tools/bp_lint.py` reads the same text UE will and
checks what can be checked without the editor: links naming a node or pin that
is not in the file, duplicate pin ids, an output wired to an output, a type
mismatch across a wire, and a non-zero literal that will silently revert. It
found ten dropped wires in `StepToward` before that graph was ever pasted.

    python tools/bp_lint.py generated/*.txt

Do them in this order. Each takes two or three minutes, except `RexAct`, whose
three wires have to be found across a very wide graph.

## Before you start

Open `BP_FightManager`. Everything below happens in it except step 4.

**Press `Home` to zoom the graph to fit.** A 122-node paste lands mostly
off-screen and there is no other way to find the entry node again. Worth
knowing before, not after.

Six things that will bite otherwise. Every one compiled clean, and four of
them produced a function that returned a constant -- which is exactly why the
self-test prints values instead of PASS/FAIL.

- **Drop each wire exactly on the pin**, not near it. Dropping near a result pin
  makes UE quietly add a second output to the function signature. It compiles
  clean and looks right. If an unexpected pin appears on the Return node,
  Ctrl+Z and try again. Dropping on a node's *body* does not auto-connect in
  5.5; it opens the node menu.
- **Paste once.** A second paste into the same graph does not replace the first,
  it stacks a second disconnected copy. Both compile. The entry feeds one copy
  and the Return node reads the other, so the function returns whatever the
  unconnected copy computes from zeroes -- `InBounds` answered `true` for every
  tile, including (-1,5). If you are unsure whether a graph was already pasted,
  Ctrl+A then Ctrl+C in the graph and count `Begin Object` lines in the
  clipboard.
- **Wire the entry's exec pin to the Return node**, the white one, even on a
  pure function. Without it the Return node never runs and the output stays at
  its default -- `InBounds` answered `false` for every tile, wiring otherwise
  perfect.
- **Never delete a Return node.** Deleting it deletes the function's output
  parameter with it, and UE then refuses to reuse that parameter name: after
  losing `IsInBounds` this way the rename silently reverted every time, while
  `IsInBound` and `Inside` were both accepted. (`Predicted` was accepted again
  later, so the refusal is not universal and I never found what holds the
  name.) Note that `Ctrl+A` then `Delete` does exactly this -- it is the
  obvious way to clear a bad paste and it is a trap; marquee-select the pasted
  nodes instead. To recover: right-click -> Add Return Node, then re-add the
  output by hand.
- **Pure nodes are re-evaluated where they are used, not once up front.** So
  the order of the impure writes at the end of a function changes what the
  pure chain feeding them reads. `RexAct` wrote RexTile before Charge, and the
  "did Rex move" test -- `Manhattan(final, RexTile) > 0` -- then read RexTile
  *after* it had already become the new tile, so it was always false and Rex
  paid HoldCost for a move it had just made. Do the write that invalidates a
  read last.
- **A pin literal that matches its autogenerated default is not that
  literal.** UE keeps a pin's value across reconstruction only while it
  differs from that pin's `AutogeneratedDefaultValue`; when the two match it
  decides the pin was never edited and rewrites it from the function's own
  signature. Those signature defaults are not always zero --
  `Add_IntInt(int32 A, int32 B = 1)`, and the same for Subtract, Divide and
  `Add_DoubleDouble`, while `JoinStringArray` declares `Separator = " "`. So
  writing `0` on a `+` node's B pin produced a 1. SpeakRead's `base + 0` for
  sealing_direction became `base + 1` and the robot spoke row 1 of
  DT_NemesisReads -- a cover_habit line, from a trigger that is not built --
  while recording row 0. `bp_gen.py` now writes an autogenerated value that
  can never match, and `bp_lint.py` fails the file if one does.
- **Only wires between pasted nodes survive.** A link naming a node that is
  not in the clipboard is deleted on paste, by name:
  `FEdGraphUtilities::PostProcessPastedNodePinLinks` calls it "a link across
  the selection set". That is why every wire to a function's entry or return
  node has to be dragged by hand and cannot be generated. It also means the
  cheapest thing a graph can do is need fewer of them: OnPlayerMove used to
  take six hand wires and now takes two, because everything that wants
  `Direction` reads one node that the entry feeds instead of reading the
  entry.
- **Generated node positions decide how much hand-wiring costs.** UE pastes a
  selection so its bounding box lands at the mouse, so putting the two or three
  nodes that need hand-wiring at the top-left of the generated coordinates
  drops them next to the entry and return nodes. `RexAct` first put them 4000
  units away at the far end of the fan-out, and finding them again cost more
  time than the rest of the graph.

## 1. InBounds  (`generated/inbounds.txt`, 8 nodes)

Open the `InBounds` function. Click its entry node, then in **Details**:

| Field | Value |
|---|---|
| Pure | tick it |
| Inputs | `Tile` — Vector 2D |
| Outputs | `Inside` — Boolean |

Then paste the file contents into the graph and make **three** wires:

    entry Tile              ->  RM_BreakT . InVec
    RM_And3 . ReturnValue   ->  Return node Inside
    entry exec (white)      ->  Return node exec

Compile. It checks `0 <= X < 10` and `0 <= Y < 10` -- the bounds are literals
because `GridSpan` is `10x10` in all three `DT_ArenaPhases` rows.

The output is `Inside`, not `IsInBounds`: UE 5.5 refuses that exact name on this
Blueprint. `tools/bp_gen.py` emits the same name, so the pasted self-test binds
to it.

## 2. Approach  (`generated/approach.txt`, 5 nodes)

Open `Approach`. Entry node, Details:

| Field | Value |
|---|---|
| Pure | tick it |
| Inputs | `Dog` — Vector 2D, then `Kid` — Vector 2D |
| Outputs | `Approach` — Float |

Paste, then **three** wires (the exec wire is already there -- this Return node
was never deleted):

    entry Dog                  ->  RM_ApMan . A
    entry Kid                  ->  RM_ApMan . B
    RM_ApClamp . ReturnValue   ->  Return node Approach

Compile. This is `1 - Manhattan(Dog, Kid) / 11` clamped 0..1. It is positional
and stores nothing -- GDD 3 exploit 4 was an approach value that only ratcheted
upward, and recomputing it every call is the fix.

`Conv_IntToDouble`, `Divide_DoubleDouble` and `FClamp` were guesses when this
was written. All three resolve on 5.5.4 -- the paste comes in clean and the
function compiles.

## 4. The self-test  (`generated/selftest.txt`, 281 nodes)

`Event BeginPlay` node is inside the paste, so the whole exec chain resolves
itself.

to take with it. In a function graph, use a marquee.

## 10. OnPlayerMove  (`generated/onplayermove.txt`, 44 nodes)

| Field | Value |
|---|---|
| Pure | leave it unticked |
| Inputs | `Direction` — String |
| Outputs | none |

Paste, then **two** wires, both from the entry node:

    entry exec (white)  ->  RM_OmBranch . execute
    entry Direction     ->  RM_OmDir . Source String

`RM_OmDir` is a To Lower, and everything that wants the direction -- the four
string compares and the append to `Moves` -- reads its output rather than the
entry's. The fan-out then lives inside the pasted set, where the text carries
it. This used to be six wires.

Both targets sit next to each other, so the fastest way to make them is to
drag the entry node itself down beside them first (its body is a large target,
its pins are three or four pixels wide), then zoom in far enough that a pin is
comfortably clickable before dragging either wire.

The round ends on `SpeakRead` then `CheckEnd` then `SyncActors`, and the whole
body is gated on `Ended` being false, so a finished fight stops accepting
moves.

**Read the entry node back after wiring any function.** Select all, Ctrl+C,
and check the `LinkedTo` on its `then` pin. A missing exec wire compiles
perfectly and does nothing, and it has now cost three separate debugging
sessions: InBounds returned a constant, and SyncActors silently never ran, so
the round loop advanced correctly while nothing moved on screen for an hour.

    PinName="then",Direction="EGPD_Output",LinkedTo=(RM_OmBranch ...)

No `LinkedTo` on that line means the function body is unreachable.

## 13. SpeakRead  (`generated/speakread.txt`, 146 nodes)

| Field | Value |
|---|---|
| Pure | leave it unticked |
| Inputs | none |
| Outputs | none |

Needs three variables on BP_FightManager: `Ended` (bool), `LastCatIndex`
(int, default -1) and `PendingLine` (string). `tools/ue_verify_speech_vars.py`
adds all three and reads them back off the class default object, which is the
only thing that proves a Blueprint variable exists --
`add_member_variable` returns a bool rather than raising, so a try/except
around it reports success for a name that was rejected.

Paste, then **one** wire: `entry exec -> RM_SrCol . execute`. The entry node
lands at the far right of the pasted block; `Home` first, then zoom in on both
ends before dragging.

The design is in `docs/UNREAL-SPEECH-PLAN.md`. The one thing to know while
editing it: the tail writes `PendingLine`, then `LastCatIndex`, then prints,
then appends to `SpokenLines`, and that order is load-bearing. The chosen line
and the chosen category are pure, so they are recomputed at each point of use,
and both of them read `LastCatIndex` and `SpokenLines`. Either write makes the
winning category ineligible and the recomputed answer falls back to row 0.
Both wrong orders shipped once: writing `LastCatIndex` first printed the wrong
sentence, and appending first reported the wrong category.

## 14. Piece motion  (`generated/motion.txt`, 8 nodes)

Into the **EventGraph** of `BP_Dog`, `BP_Rex` and `BP_Kid`. `BP_Marker` takes
`motionmarker.txt` instead, which is the same graph with the rest height at 7
rather than 5 so the cross clears the tile it sits on.

**Zero wires** -- the Tick event is in the paste. Select all and delete first:
a new Blueprint's EventGraph ships three greyed stub events, one of them Tick,
and a second Tick in the same graph is a compile error.

The actor still teleports. Only the mesh component eases, so every distance
the logic measures is unchanged and Rex arriving reads as a lunge. Doing it
the other way round -- interpolating the actor -- would have had Manhattan
returning fractions mid-slide and the veto firing on a tile nobody was on.

The component has to be Movable. `ue_dress_actors.py` sets that; a Static one
refuses to move and says nothing about it.

## 15. The HUD  (`generated/fighthud.txt`, 32 nodes)

Run `tools/ue_make_hud.py` first. It creates `BP_FightHUD` and
`BP_FightGameMode`, points the GameMode's HUDClass at the HUD, and sets
L_Arena's GameModeOverride. Without that last step the level runs on
GameModeBase, whose HUDClass is the empty default, and a perfectly correct HUD
graph draws nothing.

Then paste into **BP_FightHUD's EventGraph**. **Zero wires.**

Charge bar, stamina, round, and the last thing Rex said. Nothing here writes:
delete the whole Blueprint and the fight still plays, which is the property
that stops a HUD becoming game logic.

Two things this graph pinned down that are worth keeping:

- **`GetAllActorsOfClass` is impure.** It has exec pins, and an unconnected one
  gets the node pruned with the downstream value read as its default instead.
- **Its output array is typed to the class pin**, not to Actor, so no cast is
  needed to read the manager's variables -- and putting one in gets you
  "'Item' is already a 'BP Fight Manager', you don't need Cast To
  BP_FightManager" from the compiler. Declaring the array as Actor made the
  two pins disagree after the reconstruct and the wire was dropped, reported
  several nodes away as "the Array pin is invalid".

`AHUD::DrawText` and `DrawRect` take **floats**, not Blueprint doubles:
`PinCategory="real"` with `PinSubCategory="float"`. The wire is legal and the
compiler inserts the conversion, so `bp_lint.py` treats real-to-real as
compatible.

## The three characters

`ue_build_characters.py` builds the dog, Rex and the kid as small trees of
engine primitives hanging off each Blueprint's `Mesh` component. Neither
Kenney kit has an animal or a person in it, so the dog and the kid were the
same round mascot at two sizes and Rex was a crane -- which is what made the
board read as placeholder.

Three things it is easy to get wrong there, all of them found the hard way:

- **Everything hangs off `Mesh`.** The motion graph eases that one component
  toward the actor, so a part parented to the root teleports while the body
  slides. Rex's lamp did exactly that for a pass.
- **`Mesh` keeps its name, its rest height of 5, and stops drawing.** It is
  the pivot now, not a mesh.
- **Yaw matters more than the modelling.** Parts are authored facing +X, the
  camera looks along +Y, so +X is screen-left; a piece left at yaw 0 shows the
  camera its flank or its back. Rex read as a dark box for a whole pass
  because its visor was on the far side.

    L_Arena     the fight

`OnPlayerMove`, `OnPlayerMove` calls `SyncActors`, and `SyncActors` moves the
