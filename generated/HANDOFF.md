# Pasting the generated graphs

Eleven graphs, generated by `tools/bp_gen.py` and written here as text. UE
rebuilds nodes and wires from this text on paste, so none of it is typed by
hand.

Regenerate any of them with, for example:

    python tools/bp_gen.py inbounds > generated/inbounds.txt

**Lint before pasting.** `tools/bp_lint.py` reads the same text UE will and
checks what can be checked without the editor: links naming a node or pin that
is not in the file, duplicate pin ids, an output wired to an output, a type
mismatch across a wire, and a non-zero literal that will silently revert. It
found ten dropped wires in `StepToward` before that graph was ever pasted.

    python tools/bp_lint.py generated/*.txt

Do them in this order. Each takes two or three minutes, except `RexAct`, whose
three wires have to be found across a very wide graph.

---

## Before you start

Open `BP_FightManager`. Everything below happens in it except step 4.

**Press `Home` to zoom the graph to fit.** A 122-node paste lands mostly
off-screen and there is no other way to find the entry node again. Worth
knowing before, not after.

Six things that will bite otherwise. Every one compiled clean, and four of
them produced a function that returned a constant -- which is exactly why the
self-test prints values instead of PASS/FAIL.

- **Drop each wire exactly on the pin**, not near it. Dropping near a result pin
  makes UE quietly add a second output to the function signature. It compiles
  clean and looks right. If an unexpected pin appears on the Return node,
  Ctrl+Z and try again. Dropping on a node's *body* does not auto-connect in
  5.5; it opens the node menu.
- **Paste once.** A second paste into the same graph does not replace the first,
  it stacks a second disconnected copy. Both compile. The entry feeds one copy
  and the Return node reads the other, so the function returns whatever the
  unconnected copy computes from zeroes -- `InBounds` answered `true` for every
  tile, including (-1,5). If you are unsure whether a graph was already pasted,
  Ctrl+A then Ctrl+C in the graph and count `Begin Object` lines in the
  clipboard.
- **Wire the entry's exec pin to the Return node**, the white one, even on a
  pure function. Without it the Return node never runs and the output stays at
  its default -- `InBounds` answered `false` for every tile, wiring otherwise
  perfect.
- **Never delete a Return node.** Deleting it deletes the function's output
  parameter with it, and UE then refuses to reuse that parameter name: after
  losing `IsInBounds` this way the rename silently reverted every time, while
  `IsInBound` and `Inside` were both accepted. (`Predicted` was accepted again
  later, so the refusal is not universal and I never found what holds the
  name.) Note that `Ctrl+A` then `Delete` does exactly this -- it is the
  obvious way to clear a bad paste and it is a trap; marquee-select the pasted
  nodes instead. To recover: right-click -> Add Return Node, then re-add the
  output by hand.
- **Pure nodes are re-evaluated where they are used, not once up front.** So
  the order of the impure writes at the end of a function changes what the
  pure chain feeding them reads. `RexAct` wrote RexTile before Charge, and the
  "did Rex move" test -- `Manhattan(final, RexTile) > 0` -- then read RexTile
  *after* it had already become the new tile, so it was always false and Rex
  paid HoldCost for a move it had just made. Do the write that invalidates a
  read last.
- **Generated node positions decide how much hand-wiring costs.** UE pastes a
  selection so its bounding box lands at the mouse, so putting the two or three
  nodes that need hand-wiring at the top-left of the generated coordinates
  drops them next to the entry and return nodes. `RexAct` first put them 4000
  units away at the far end of the fan-out, and finding them again cost more
  time than the rest of the graph.

## 1. InBounds  (`generated/inbounds.txt`, 8 nodes)

Open the `InBounds` function. Click its entry node, then in **Details**:

| Field | Value |
|---|---|
| Pure | tick it |
| Inputs | `Tile` — Vector 2D |
| Outputs | `Inside` — Boolean |

Then paste the file contents into the graph and make **three** wires:

    entry Tile              ->  RM_BreakT . InVec
    RM_And3 . ReturnValue   ->  Return node Inside
    entry exec (white)      ->  Return node exec

Compile. It checks `0 <= X < 10` and `0 <= Y < 10` -- the bounds are literals
because `GridSpan` is `10x10` in all three `DT_ArenaPhases` rows.

The output is `Inside`, not `IsInBounds`: UE 5.5 refuses that exact name on this
Blueprint. `tools/bp_gen.py` emits the same name, so the pasted self-test binds
to it.

## 2. Approach  (`generated/approach.txt`, 5 nodes)

Open `Approach`. Entry node, Details:

| Field | Value |
|---|---|
| Pure | tick it |
| Inputs | `Dog` — Vector 2D, then `Kid` — Vector 2D |
| Outputs | `Approach` — Float |

Paste, then **three** wires (the exec wire is already there -- this Return node
was never deleted):

    entry Dog                  ->  RM_ApMan . A
    entry Kid                  ->  RM_ApMan . B
    RM_ApClamp . ReturnValue   ->  Return node Approach

Compile. This is `1 - Manhattan(Dog, Kid) / 11` clamped 0..1. It is positional
and stores nothing -- GDD 3 exploit 4 was an approach value that only ratcheted
upward, and recomputing it every call is the fix.

`Conv_IntToDouble`, `Divide_DoubleDouble` and `FClamp` were guesses when this
was written. All three resolve on 5.5.4 -- the paste comes in clean and the
function compiles.

## 4. The self-test  (`generated/selftest.txt`, 187 nodes)

Open **`BP_SelfTest`** (a different asset), go to its **EventGraph**.

Select all (Ctrl+A), delete, then paste the file. **Zero wires needed** -- the
`Event BeginPlay` node is inside the paste, so the whole exec chain resolves
itself.

Ctrl+A is safe *here* and only here: an event graph has no return node for it
to take with it. In a function graph, use a marquee.

## 8. SyncActors  (`generated/syncactors.txt`, 14 nodes)

Create the function first -- unlike the others it is not in the list
`tools/ue_build_fightmanager.py` makes.

| Field | Value |
|---|---|
| Pure | leave it unticked |
| Inputs | `Marker` — Vector 2D |
| Outputs | none |

Paste, then **two** wires:

    entry exec (white)      ->  RM_SyFind0 . execute
    entry Marker            ->  RM_SyTw2 . Tile

The paste drops a `Rex Tile` getter on top of RM_SyFind0's execute pin. Move it
out of the way before wiring, or the drag grabs the getter instead and the exec

Then set the three `Actor Class` pins by hand to BP_Dog, BP_Rex and BP_Marker.
The generator emits the right literal now, but a graph pasted before that fix
shows "Select Class" on all three, with no error anywhere.

## 10. OnPlayerMove  (`generated/onplayermove.txt`, 38 nodes)

| Field | Value |
|---|---|
| Pure | leave it unticked |
| Inputs | `Direction` — String |
| Outputs | none |

Paste, then **six** wires, all from the entry node. The five nodes that take
`Direction` are placed together at the top-left so the paste drops them within
reach of it.

    entry exec (white)  ->  RM_OmBranch . execute
    entry Direction     ->  RM_OmEqL . A
    entry Direction     ->  RM_OmEqR . A
    entry Direction     ->  RM_OmEqU . A
    entry Direction     ->  RM_OmEqD . A
    entry Direction     ->  RM_OmAddMove . NewItem

**Read the entry node back after wiring any function.** Select all, Ctrl+C,
and check the `LinkedTo` on its `then` pin. A missing exec wire compiles
perfectly and does nothing, and it has now cost three separate debugging
sessions: InBounds returned a constant, and SyncActors silently never ran, so
the round loop advanced correctly while nothing moved on screen for an hour.

    PinName="then",Direction="EGPD_Output",LinkedTo=(RM_OmBranch ...)

No `LinkedTo` on that line means the function body is unreachable.

## 11. The keys  (`generated/inputkeys.txt`, 18 nodes)

Into **BP_FightManager's EventGraph** alongside BeginPlay. **Zero wires.**

Nine raw key events -- WASD, the arrows, space to wait -- each calling
OnPlayerMove. They only fire if the actor is receiving input, which
`tools/ue_build_arena.py` sets when it places the manager. Without that the
whole round loop is unreachable and pressing W does nothing.
